# Личный Telegram-помощник

**Версия 4.1.2 · Windows и macOS · Python · Локальное хранение данных**

Помощник запускается на вашем компьютере. Вы управляете им через своего Telegram-бота, а стикеры и голосовые отправляются с вашего личного аккаунта. Доступ к управлению получает только аккаунт, которым выполнен вход.

Сейчас доступен один режим: **стикер → ГС1 → ответ собеседника → ваше подтверждение → ГС2**.

## Как работает переписка

1. Вы отправляете боту `@username` или ссылку `https://t.me/username`.
2. Если вы уже писали человеку, бот сначала просит подтвердить начало переписки.
3. Перед каждым исходящим сообщением помощник прочитывает доступные сообщения чата и выдерживает **3 секунды** после чтения. Новое входящее запускает этот интервал заново.
4. Отправляется выбранный стикер. Чат архивируется, уведомления отключаются, чат попадает в папку **В процессе 1**.
5. Перед ГС1 показывается индикатор записи на длительность выбранной записи. Затем отправляется сохранённое голосовое **без пометки о пересылке**. Микрофон не используется.
6. Ответ на стикер прочитывается и переносит чат в **В процессе 2**, но не отменяет ГС1.
7. После **нового ответа, пришедшего после ГС1**, бот присылает username, ссылку на чат и кнопку **🎙 Отправить ГС2**.
8. Вы открываете переписку, отвечаете человеку вручную и возвращаетесь в бот. Только после нажатия кнопки помощник готовит ГС2: чтение → 3 секунды → индикатор записи → отправка.
9. После ГС2 задание завершается. Архив и отключение уведомлений проверяются после отправок.

**Каждое ГС2 требует подтверждения владельца.** Если до отправки ГС2 приходит новый вопрос со знаком `?`, `？` или `؟`, прежнее разрешение отзывается и появляется новый запрос. Голосовые ответы не расшифровываются; знаки вопроса проверяются в тексте.

Во время ожидания ответа после ГС1 и вашего подтверждения новые сообщения остаются непрочитанными: вы открываете чат сами. Перед отправкой ГС2 помощник прочитает оставшиеся сообщения. После завершения задания он больше не читает новые ответы.

**Если голосовые запрещены**, помощник останавливает отправки и сообщает об этом владельцу. Текстовых замен нет. Если запрет известен до начала сценария, не отправляется даже стикер. Если запрет появляется позднее или Telegram возвращает его только при попытке отправки, уже доставленные сообщения остаются в чате.

## Что понадобится

- Личный Telegram-аккаунт и доступ к подтверждению входа.
- Свой бот, созданный через [@BotFather](https://t.me/BotFather).
- Компьютер с интернетом и Python **3.10+**. Для новой установки рекомендуем Python **3.14**; проверки этой версии помощника выполнены на macOS с Python 3.14.
- Для входа: Telegram/AyuGram на телефоне со сканером QR либо своя авторизованная папка `tdata` от AyuGram Desktop.

Python скачивайте с [официального сайта](https://www.python.org/downloads/). Git не обязателен: достаточно ZIP-архива репозитория.

### Получение токена бота

1. Откройте [@BotFather](https://t.me/BotFather) и отправьте `/newbot`.
2. Задайте название и username бота.
3. Сохраните выданный токен. При настройке вставьте его в терминал и нажмите Enter. **Символы при вводе не отображаются** — это ожидаемо.

Если бот уже создан, используйте его существующий токен. [Официальная инструкция Telegram](https://core.telegram.org/bots/tutorial#obtain-your-bot-token).

Собственные `TG_API_ID` и `TG_API_HASH` вводить не нужно: используется встроенный API-профиль Telegram Desktop из OpenTele2. Это сторонний клиент; серверные ограничения Telegram сохраняются.

## Установка на Windows

### Быстрый запуск

1. Установите Python с официального сайта. Убедитесь, что доступна команда `py` — её использует `start.bat`.
2. На странице репозитория выберите **Code → Download ZIP** и полностью распакуйте архив в постоянную папку, например `C:\TelegramAssistant`. Не запускайте программу внутри ZIP.
3. Откройте PowerShell и проверьте Python:

   ```powershell
   py -3 --version
   ```

4. Дважды нажмите **start.bat** в распакованной папке.
5. Дождитесь создания `.venv` и установки библиотек.
6. Введите токен BotFather и выполните вход по инструкции ниже.
7. После сообщения о запуске откройте своего бота в Telegram и нажмите **Start**.

**Окно терминала должно оставаться открытым.** В Windows этот запуск работает в терминале; встроенная фоновая служба и автоматический перезапуск предусмотрены для macOS. Для остановки нажмите **Ctrl+C**. При запросе завершения пакетного файла подтвердите его.

Повторный запуск через `start.bat` использует сохранённые токен, сессию и очередь. Он проверяет зависимости и существующий вход, но не должен заново запрашивать авторизацию.

### Ручная установка и запуск в PowerShell

В примере замените путь на свою распакованную папку:

```powershell
cd "C:\TelegramAssistant"
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m assistant setup
.\.venv\Scripts\python.exe -m assistant run
```

Для следующих запусков достаточно:

```powershell
cd "C:\TelegramAssistant"
.\.venv\Scripts\python.exe -m assistant run
```

Активировать окружение не требуется — команды обращаются прямо к его Python. Если `py` не найден, но `python --version` показывает подходящий Python 3, в команде создания `.venv` можно заменить `py -3` на `python`. Либо установите Python с поддержкой команды `py`, чтобы пользоваться `start.bat`.

## Установка на macOS

### Быстрый запуск

1. Установите Python с [python.org](https://www.python.org/downloads/), если подходящего Python ещё нет.
2. Скачайте **Code → Download ZIP**, распакуйте проект в постоянную папку, например `~/Documents/TelegramAssistant`.
3. В Terminal проверьте:

   ```bash
   python3 --version
   ```

4. Откройте **start.command**. Если двойной щелчок не запускает файл, выполните в Terminal:

   ```bash
   cd "$HOME/Documents/TelegramAssistant"
   bash start.command
   ```

5. Дождитесь установки зависимостей, введите токен BotFather и выполните вход.
6. После сообщения о фоновом запуске откройте своего бота в Telegram и нажмите **Start**.

После успешного запуска **Terminal можно закрыть**. Бот работает в фоне в сеансе вашего пользователя, запускается после входа в macOS и перезапускается после сбоя. При изменении Python-файлов или `.env` служба ждёт две секунды без изменений и перезапускает программу. После аварийного завершения повторный запуск происходит через 15 секунд.

Компьютер должен быть включён и подключён к интернету. Во время сна или выключения бот не работает; после восстановления продолжает очередь.

### Ручная установка

```bash
cd "$HOME/Documents/TelegramAssistant"
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m assistant setup
.venv/bin/python -m assistant.service install
```

Последняя команда включает фоновую службу. Для запуска непосредственно в Terminal сначала остановите службу:

```bash
.venv/bin/python -m assistant.service stop
.venv/bin/python -m assistant run
```

При таком ручном запуске окно Terminal должно оставаться открытым; остановка — **Ctrl+C**. Не запускайте одновременно фоновую и ручную копии с одним каталогом данных.

## Вход в Telegram

Помощник создаёт **отдельную сессию того же аккаунта**. Это новый вход в списке устройств, а переписки общие для всех ваших устройств. Подробности: [ВХОД.md](ВХОД.md).

### Вариант 1: QR с телефона

1. В терминале выберите **1 — QR**.
2. Откроется локальная страница с QR-кодом.
3. На телефоне в нужном аккаунте откройте **Настройки → Устройства → Подключить устройство**.
4. Отсканируйте QR и подтвердите вход.
5. Если включена двухэтапная защита, введите её облачный пароль **в терминале**.

Код обновляется автоматически, временная страница удаляется после завершения настройки. `my.telegram.org` для этого способа не нужен. [Механизм QR-входа Telegram](https://core.telegram.org/api/qr-login).

### Вариант 2: отдельный вход из tdata AyuGram Desktop

1. Найдите свою авторизованную папку `tdata`. В портативной версии она обычно рядом с приложением. Если путь неизвестен, проверьте рабочий каталог клиента или его `log.txt`; конкретное расположение зависит от сборки.
2. Полностью закройте AyuGram, включая значок в системном трее Windows. **Не выходите из аккаунта**: авторизация должна остаться в `tdata`.
3. В настройке помощника выберите **2 — tdata** и укажите полный путь к самой папке.
4. При запросе введите локальный код-пароль AyuGram. Если его нет, нажмите Enter. Это отдельный пароль от облачной двухэтапной защиты.
5. Если аккаунтов несколько, выберите нужный. При запросе облачного пароля введите и его.
6. Дождитесь сообщения **«Создан отдельный ключ входа»**. После настройки AyuGram можно снова открыть.

Исходная авторизация используется в памяти для подтверждения нового входа. `tdata` не перезаписывается, исходный ключ не сохраняется как постоянная сессия помощника. Совместимость со всеми сборками AyuGram не гарантируется; при проблемах используйте QR.

Принудительно выбрать способ входа можно при ручной настройке:

| Система | QR | tdata |
| --- | --- | --- |
| Windows / PowerShell | `.\.venv\Scripts\python.exe -m assistant setup --login qr` | `.\.venv\Scripts\python.exe -m assistant setup --login tdata` |
| macOS | `.venv/bin/python -m assistant setup --login qr` | `.venv/bin/python -m assistant setup --login tdata` |

Если вы меняли API-профиль AyuGram, добавьте `--source-api android`, `ios`, `macos` или `desktop` в соответствии с вашим клиентом. Для QR без автоматического открытия браузера добавьте `--no-browser`; путь к локальной странице появится в терминале.

### Проверка отдельной сессии

В Telegram откройте **Настройки → Устройства** и найдите новый вход с моделью **Personal Telegram Assistant**. Название приложения может отображаться как Telegram Desktop. Сессия помощника хранится в `data/assistant-user.session` и повторно используется при следующих запусках.

Чтобы отозвать доступ, остановите помощника и завершите именно этот вход в списке устройств Telegram. Для создания ещё одной новой сессии остановите программу и задайте новый `DATA_DIR`, например `data-second`, затем выполните setup. Новый каталог получит свою очередь и настройки.

## Настройка стикера и голосовых

1. В своём боте нажмите **Start → ⚙️ Настройка**.
2. Выберите режим **Стикер + ГС1 + ГС2**.
3. Нажмите **Выбрать стикер** и отправьте нужный стикер боту.
4. Нажмите **Задать ГС1** и отправьте либо перешлите первое голосовое боту.
5. Нажмите **Задать ГС2** и отправьте либо перешлите второе голосовое боту.

Нужно именно голосовое сообщение, а не аудиофайл или видеокружок. После сохранения бот подтверждает настройку. Кнопок выбора ГС из Избранного нет: запись передаётся прямо в чат с ботом. Помощник сохраняет её копию в Избранном вашего аккаунта для последующих отправок. Не удаляйте эти сохранённые копии, пока задания используют их.

Настройки фиксируются отдельно для каждого задания. Изменение записи применяется к новым заданиям и новым запросам повтора; уже начатые задания продолжают со своими выбранными медиа.

## Запуск переписки и повторная отправка

Отправьте боту один `@username` или ссылку `https://t.me/username`. В ответ появится номер задания — его можно использовать с `/cancel` и `/retry`.

Если вы раньше писали человеку, бот покажет предупреждение и кнопку **Подтвердить начало**. До нажатия новый сценарий не отправляет сообщения.

Если человек уже есть в очереди, бот предлагает **✅ Подтвердить повтор**. Эта кнопка создаёт новый цикл со стикером и ГС1, заменяя прежнее задание. Для ГС2 всё равно требуются новый ответ после нового ГС1 и отдельная кнопка владельца. Повтор разрешён и после завершения или отмены задания; запрет голосовых проверяется заново.

До подтверждения повтора прежнее задание продолжает работать. **Отмена повтора** отменяет только запрос на новый цикл. Запрос сохраняется после перезапуска, `/status` восстанавливает кнопку. При новом запросе действует только последняя кнопка. Двойное нажатие и старые кнопки не отправляют дубликаты; результат заменённого задания сохраняется в локальной истории.

### Длительность записи и момент отправки

Используется длительность голосового из метаданных Telegram, включая дробные секунды. Индикатор обновляется каждые четыре секунды. Во время записи история не опрашивается каждую секунду: входящие обрабатываются по событиям. Перед отправкой история и доступность голосовых проверяются повторно.

В 4.1.2 убраны повторные проверки в конце записи и предварительное выключение индикатора перед обычной отправкой. Запрос отправки идёт перед отдельным запросом снятия индикатора, чтобы между ними не образовывалась искусственная пауза. Если новые входящие требуют выдержать 3 секунды после чтения, индикатор останавливается и сообщение ждёт окончания интервала.

Фактическое отображение индикатора и доставка зависят от клиента Telegram, сети и нагрузки компьютера. Точность до миллисекунды не гарантируется; искусственной паузы на две секунды после записи нет.

## Команды

| Команда | Действие |
| --- | --- |
| `/start`, `/help` | Инструкция и главное меню |
| `/settings` | Настройка режима, стикера, ГС1 и ГС2 |
| `/status` | Состояние заданий; восстановление кнопок ГС2 и повтора |
| `/version` | Текущая версия программы |
| `/pause` | Приостановить отправки и выключить индикаторы записи |
| `/resume` | Продолжить очередь |
| `/cancel ID` | Отменить задание, например `/cancel 25` |
| `/retry ID` | Повторить незавершённый шаг после ошибки |
| `/cancel` | Отменить ввод настройки; задание эта команда не отменяет |

`/retry` не создаёт новый цикл, не возобновляет завершённое/отменённое задание и не заменяет разрешение на ГС2. Для новой отправки завершённого сценария пришлите username и подтвердите повтор.

## Остановка и перезапуск

| Действие | Windows | macOS |
| --- | --- | --- |
| Приостановить отправки | `/pause` в боте | `/pause` в боте |
| Продолжить очередь | `/resume` | `/resume` |
| Полностью остановить | Ctrl+C в окне программы | `stop.command` или `bash stop.command` |
| Запустить снова | `start.bat` | `start.command` или `bash start.command` |
| Перезапустить | Ctrl+C, затем `start.bat` | `restart.command` или `bash restart.command` |
| Проверить фоновую службу | Не предусмотрена этим запуском | `status.command` или `bash status.command` |

`/pause` оставляет бот доступным для команд. Полная остановка выключает процесс. На Mac `stop.command` также отключает автозапуск при входе; `start.command` включает его снова. Настройки, сессии и очередь сохраняются.

После перезапуска входящие проверяются заново. Прерванный индикатор записи начинается на полную длительность, а подтверждение ГС2 сохраняется, пока новый вопрос его не отзовёт. Повторная сетевая попытка использует прежний Telegram `random_id`, чтобы не создать дубликат.

## Обновление и резервная копия

1. Полностью остановите помощника способом для вашей ОС.
2. Скопируйте **`.env` и весь каталог `data`** в защищённое локальное место. Если настроен другой `DATA_DIR`, сохраните именно его. В `data` находятся и настройки, и очередь, и ключи входа.
3. Замените программные файлы новыми из ZIP, сохранив `.env` и каталог данных. Не удаляйте старую папку программы до проверки обновления.
4. Запустите `start.bat` или `start.command`: зависимости будут проверены.
5. В Telegram выполните `/version` и `/status`. Для этого релиза версия — **4.1.2**.

При переносе на другую ОС `.venv` нужно создать заново, а не копировать. Не запускайте один файл сессии одновременно на двух компьютерах; для второго компьютера создайте отдельный вход. Резервные копии сессий храните как пароли, а не в репозитории GitHub.

Для старых очередей 3.x: незавершённые отправки переводятся в единый режим; ожидавшие ГС2 требуют нового подтверждения. Если у старого задания не выбрано ГС2, задайте запись и выполните `/retry ID`. Старые текстовые цепочки останавливаются и больше не отправляются. Завершённые задания автоматически не возобновляются.

## Частые вопросы и ошибки

| Ситуация | Что делать |
| --- | --- |
| Снова просит токен | Проверьте, что запускаете прежнюю папку, в ней сохранён `.env`, а `TG_BOT_TOKEN` заполнен. При переходе в новую папку перенесите `.env` и данные после остановки программы. |
| Ввод токена или пароля «ничего не печатает» | Ввод скрыт. Вставьте значение и нажмите Enter. |
| `py` или `python3` не найден | Установите Python и откройте новый терминал. В Windows используйте ручной вариант с `python`, если доступна именно эта команда. |
| PowerShell запрещает `Activate.ps1` | Активация не нужна. Используйте `.\.venv\Scripts\python.exe`, как в инструкции. |
| Mac не запускает `.command` | Откройте Terminal в папке и выполните `bash start.command`. |
| Предупреждение pip об обновлении | Это уведомление об установщике, а не ошибка бота. Ориентируйтесь на последующие сообщения. |
| QR истёк | Дождитесь нового QR и повторите сканирование. Проверьте, что на телефоне выбран нужный аккаунт. |
| Ошибка чтения tdata | Полностью закройте AyuGram, проверьте путь и локальный пароль. При несовместимости используйте QR. |
| «Нужно именно голосовое сообщение» | Пришлите голосовое, записанное в Telegram, а не файл MP3/OGG или видеокружок. |
| Медиа не сохранилось или удалено | Повторно отправьте его боту при настройке; не удаляйте сообщение до подтверждения сохранения. |
| «Не принимает голосовые» | Сценарий остановлен. Текстовых замен и дальнейших сообщений не будет. |
| `Telegram просит подождать N сек.` | Сервер вернул FLOOD_WAIT. Бот ждёт указанное время с небольшим запасом и продолжает автоматически. Повторно подтверждать задание не нужно. [О лимитах Telegram](https://core.telegram.org/api/errors#420-flood). |
| ГС2 не отправляется | Нужен новый ответ после ГС1, затем ваше нажатие «Отправить ГС2». Новый вопрос отзывает старое подтверждение. Кнопку можно восстановить через `/status`. |
| Папка, архив или отключение звука не применились | Посмотрите ошибку в `/status`. Бот повторяет эти действия отдельно, не пересылая уже доставленное сообщение. При дублирующихся папках оставьте по одной обычной папке с нужным названием. |
| «Помощник уже запущен» | Остановите прежнюю копию; не удаляйте файлы сессии или очередь. На Mac проверьте `status.command`. |
| Компьютер уснул | Отправки продолжатся после пробуждения и восстановления интернета. |

На macOS журналы находятся в `~/Library/Logs/TelegramAssistant/service.log` и `service-error.log`. Файл автозапуска — `~/Library/LaunchAgents/local.personal.telegram-assistant.plist`. В Windows сообщения об ошибках видны в окне программы. Перед передачей логов другому человеку удалите из них личные данные.

## Данные и структура проекта

Создать `.env` вручную можно по образцу `.env.example`:

```dotenv
TG_BOT_TOKEN=YOUR_BOT_TOKEN
DATA_DIR=data
```

Либо просто введите токен при первом setup — программа сохранит его сама. Переменные окружения имеют приоритет над `.env`; относительный `DATA_DIR` считается от папки программы.

| Файл или каталог | Назначение |
| --- | --- |
| `assistant/app.py` | Меню, обработка сообщений, сценарий, таймеры и очередь |
| `assistant/auth.py` | QR-вход и создание новой сессии из tdata |
| `assistant/store.py` | SQLite, настройки, задания и история повторов |
| `assistant/folders.py` | Папки Telegram |
| `assistant/service.py` | Фоновая служба macOS и перезапуск |
| `assistant/lock.py` | Защита от одновременного запуска с одним каталогом данных |
| `tests/` | Проверки без реальных отправок |
| `requirements.txt` | Закреплённые версии зависимостей |
| `.env` | Локальный токен и путь к данным; не публикуется |
| `data/queue.sqlite3` | Очередь, настройки и выбранные медиа |
| `data/assistant-user.session` | Ключ отдельного входа личного аккаунта |
| `data/assistant-bot.session` | Авторизация управляющего бота |
| `.venv/` | Локальное окружение Python; пересоздаётся при установке |

В репозиторий входят только программные файлы, инструкции и пример конфигурации. Токен, реальные `.env`, `tdata`, `.session`, базы переписок, резервные копии и виртуальное окружение в него не входят. Даже приватный репозиторий не используйте для хранения этих данных.

## Проверки

На macOS:

```bash
.venv/bin/python -m unittest discover -s tests
```

На Windows основной сценарий и вход можно проверить отдельно от тестов службы macOS:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_assistant.py
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_auth.py
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_migration.py
```

Тесты используют временные базы, поддельный Telegram-клиент и управляемое время. Они проверяют чтение и интервалы, порядок отправки и выключения индикатора, длинные записи, подтверждения ГС2, повторные сценарии, запреты голосовых, восстановление после сбоев, архивирование и сохранение медиа. **87 проверок прошли на macOS.** Полный запуск Windows на настоящем компьютере в этой среде не проверялся.

Документация используемых механизмов: [Telethon](https://docs.telethon.dev/), [OpenTele2](https://opentele2.github.io/documentation/), [виртуальные окружения Python](https://docs.python.org/3/library/venv.html).
